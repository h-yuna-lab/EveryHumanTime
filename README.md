## 💡 기획 배경

대학생이 자주 사용하는 시간표, 학점 계산, 커뮤니티, 열람실, 중고책 거래 등의 기능이 여러 서비스에 분산되어 있다는 불편함에서 시작했습니다.

에브리휴먼타임은 대학 생활에 필요한 기능을 하나의 서비스에 통합하여 다음과 같은 가치를 제공하는 것을 목표로 했습니다.

- 시간표와 학점 계산을 통한 학사 관리
- 게시판과 쪽지를 통한 사용자 간 소통
- 열람실 좌석 예약을 통한 편의성 향상
- 중고책 거래를 통한 학생 간 거래 지원
- 스도쿠를 통한 간단한 여가 기능 제공

## 🙋‍♀️ 담당 기능 — 열람실 예약

프론트엔드에서 **열람실 좌석 예약의 전체 사용자 흐름**을 담당했습니다.

### 구현 내용

- 전체 좌석 수, 빈 좌석 수, 이용 중 좌석 수를 요약 정보로 표시
- 제1 열람실과 제2 열람실을 탭으로 구분
- 좌석 번호가 실제 열람실 배치처럼 보이도록 좌석 배치도 구성
- 빈 좌석을 선택하면 예약 모달을 열고 이용 시간을 선택하도록 구현
- 예약된 좌석을 선택하면 입실 시간, 종료 예정 시간, 남은 시간을 표시
- 퇴실 및 예약 취소 후 좌석 상태와 상단 좌석 현황이 함께 변경되도록 처리
- 빈 좌석과 사용 중 좌석을 서로 다른 상태로 표현해 사용자가 쉽게 구분하도록 구성

### 사용자 흐름

```text
열람실 메뉴 진입
    ↓
제1·제2 열람실 선택
    ↓
빈 좌석 및 이용 중 좌석 현황 확인
    ↓
빈 좌석 선택
    ↓
이용 시간 선택
    ↓
좌석 배정
    ↓
이용 정보 및 남은 시간 확인
    ↓
퇴실 또는 배정 취소
```

### 구현 포인트

- 좌석 상태 변경과 상단 통계 정보가 일치하도록 화면 상태를 함께 갱신했습니다.
- 사용 중인 좌석은 다시 예약할 수 없도록 예약 화면과 이용 정보 화면을 구분했습니다.
- 사용자가 현재 좌석 상태를 빠르게 파악할 수 있도록 좌석 색상과 요약 정보를 활용했습니다.
- 예약부터 취소까지의 작업을 모달 안에서 완료할 수 있도록 사용자 동선을 단순화했습니다.

## 프로젝트 회고

### 좌석 배치도와 예약 상태를 함께 관리한 경험

프론트엔드에서 열람실 좌석 예약·배정·취소를 담당했습니다. 좌석을 배치도에 표시하는 것뿐 아니라 빈 좌석 선택, 이용 시간 선택, 예약 완료, 이용 정보 확인, 퇴실까지 하나의 흐름으로 연결해야 했습니다. 예약 후 좌석 색상만 바꾸면 전체 이용 중·빈 좌석 수가 달라질 수 있어, 좌석 상태와 요약 정보가 같은 데이터를 기준으로 표시되도록 구성하는 것이 중요했습니다.

두 열람실의 224개 좌석을 상태로 관리하고, 서버에서 받은 예약 정보를 좌석 번호와 연결했습니다. 빈 좌석은 배정 모달을 열고 사용 중인 좌석은 입실·종료 시각과 남은 시간을 보여 주도록 구분했습니다. 예약 API가 성공한 뒤 해당 좌석의 이용 상태를 변경하고, 모달을 닫거나 퇴실을 완료하면 서버 현황을 다시 조회하도록 연결했습니다. 이용 중·빈 좌석 수는 좌석 상태에서 계산해 개별 표시 값을 따로 관리하는 일을 줄였습니다.

이 과정에서 화면의 상태와 서버의 예약 데이터가 항상 같다고 가정하면 안 된다는 점을 배웠습니다. 사용자에게 보여 주는 성공 메시지뿐 아니라 이후의 좌석 상태와 이용 정보까지 일치해야 예약 흐름이 완성된다는 점을 느꼈습니다.

### 이용 시간과 퇴실 처리를 화면에 연결

시간제 좌석 예약에서는 이용 시간이 끝났는데도 좌석이 계속 사용 중으로 보이지 않도록 처리할 필요가 있었습니다. 입실 시간을 서버에 전달하고 종료 시각을 화면에 표시하는 과정에서도 날짜 형식과 시간대 기준을 맞춰야 했습니다.

현재 구현에서는 입실 시각을 브라우저의 시간대 오프셋으로 보정한 문자열로 전송하고, 서버가 반환한 종료 시각으로 남은 시간을 계산합니다. 좌석 현황은 페이지 진입 시와 1분 간격으로 조회합니다. 백엔드가 조회 시 만료 예약을 정리하는 흐름에 맞춰, 이용 정보 모달에서도 종료 시각을 확인해 시간이 지나면 안내 후 모달을 닫고 현황을 다시 불러오도록 구성했습니다.

직접 퇴실할 때는 선택한 예약 번호와 로그인 사용자 ID를 확인하고, 본인이 예약한 좌석인 경우에 반납 API를 호출하도록 연결했습니다. 퇴실 성공 후에는 최신 현황을 다시 조회합니다. 프론트엔드는 이용 상태를 안내하고 요청을 보내는 역할이며, 실제 예약·만료·반납 데이터 처리는 백엔드와 맞춰야 한다는 점을 배웠습니다.

### 앞으로 보완할 부분

현재는 선택한 열람실의 현황만 갱신하므로, 다른 열람실에서 변경된 예약이 상단 전체 현황에 늦게 반영될 수 있습니다. 두 열람실을 함께 조회하거나 전체 현황 API를 사용하는 방식으로 개선하고 싶습니다. 또한 1분 주기의 갱신은 상태 반영에 지연이 생길 수 있어, 남은 시간 표시와 서버 재조회 주기를 구분하고 예약·만료·퇴실 이후의 표시를 테스트로 확인할 필요가 있습니다.

조회 실패가 콘솔에만 기록되는 부분은 화면의 오류 안내와 재시도 기능으로 보완해야 합니다. 입실 시간은 클라이언트 시계에 의존하고 있으므로 서버 기준 시각과 공통 시간대 규칙을 백엔드 담당자와 맞추고 싶습니다. 같은 좌석에 동시에 예약 요청이 들어오는 경우도 팀과 함께 검증하고, 새로고침·열람실 전환·이용 시간 만료·다른 사용자의 퇴실 시도까지 테스트 시나리오로 남기겠습니다.

회고는 원본의 최종 업로드 커밋과 개인 담당 코드에서 확인되는 구현을 기준으로 작성했습니다. 원본 커밋은 팀원이 파일을 통합해 업로드한 기록입니다.
